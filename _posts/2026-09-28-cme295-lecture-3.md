[This lecture](https://www.youtube.com/watch?v=Q5baLehv5So&list=PLoROMvodv4rOCXd21gf0CF4xr35yINeOy&index=4) provides a comprehensive technical overview of Large Language Models (LLM), focusing on the architecture, generation strategies, and efficiency optimizations. 

Interestingly, the lecture re-build the definition of large language models, excluding 'BERT' from the family of LLMs. In the early days, any large transformer was included into the "LLM" category. Today, the definition of LLM has narrowed to a strict "text-to-text" and "decoder-only model". BERT is an encoder-only model which creates embeddings for classification or sentiment analysis, but it doesn't generate sequences of text. With the trend, BERT would not be an LLM model. 

**Large Language Models** are defined by their ability to assign probabilities to sequences of tokens, effectively predicting the next token in a series. 

-   Model size : typically billions or even hundreds of billions of parameters. 
-   Data : pre-trained on hundreds of billions or trillions of tokens. 
-   Compute : they require significant hardware for training and inference. 

# MoE-based LLMs 

Modern largue language models are decoder-only transformer models. They have a lot of parameters and require massive computational power and data for training and inference. To manage this computational pressure, researchers use the **Mixture of Experts (MoE)** approach to scale the model's knowledge without increasing the cost of running it. The approach is basically based on the question "How do we scale a model to billions of parameters without the compute costs? 

The main idea behind MoE is that we do not need every single parameter of a massive model to be active for every single token it generates. 

Imagine a room with a mathematician and a historian. If we have a math question, it is inefficient to ask both to calculate the answer. In this case, we should only ask the mathematician, the expert. 

An MoE model consists of two main parts that work together during inference.

-   **Experts (E)**: The experts are several independent sub-networks within each layer of the transformer. These networks are placed in the **Feed-Forward Neural Network** (FFN) because it is the most parameter-heavy part of the architecture.

-   **Router or Gate (G)**: This is a small, trainable network that looks at an incoming token and decides which expert is best suited to handle it.

The MoE replaces the standard FFN block with several expert networks. A gate (or router) takes the representation of each individual token and decides which expert is best suited to process it. This routing happens at the token level, meaning different tokens in the same sentence might be processed by different experts.

There are two ways to weight these experts. **Dense MoE** approach involves all experts but gives more weight to the most relevant experts. This type doesn't save much on computation because everyone is still involved. In a **Sparse MoE**, a router or gate selects the top-K experts (usually 1 or 2) to process a token. This type reduces the FLOPs (Floating Point Operations), meaning the model does not need to quantify how heavy the computation is for each forward pass, while still having access to total parameters. 

For better understanding, FLOPs is a unit of measure to determine how compute-heavy a specific task or model is. When comparing different architectures, a Sparse MoE model has a lower number of FLOPs compared to a Dense MoE model, because it performs fewer operations per token. 

Experts (E) and the Gate (G) are trained jointly using standard backprogation. However, the training process often encounters a challenge, which is called '**Routing Collapse**'. It refers a situation where the router consistently choose only a few experts, while the rest remain inactive or are never involved in the computation. To prevent Routing Collapse, engineers add an extra term to the loss function to foce the router to distribute tokens uniformly across the expert pool. 

# Decoding Strategies - How Models Choose Next Tokens?

The difference between MoE training and decoding strategies is the difference between how a model calculate its knowledge and how it expresses the knowledge as a final response. 

In a MoE training process, a router decides which experts should handle a specific token. These experts process the information to produce a set of numbers called logits. These logits are then passed through a softmax layer at the very top of the architecture to turn them into a final probability distribution that sums to 1.0. 

Once the MoE layers have provided a probability distribution, the decoding strategy takes over to choose the actual word to print. 

## 1\. Greedy Decoding 

It works by selecting the token with the absolute highest probabilities at every step, which should lead to the same sequence of words every time. In other words, it should always produce the exact same answer for the same question. 

## 2\. Beam Search 

Instead of just picking one word, it keeps track of the K-most probable paths (beam width) to find a sequence that is more globally optimal over time. Starting from the BOS (Beginning of Sentence) token, the model identifies the top K tokens. At the next step, it evaluates the next possible tokens for all K branches and again selects only the top K most likely overall sequences to keep. 

Beam search is more compute-heavy than greedy decoding because it tracks and evaluates multiple paths simultaneously. The method is commonly used for machine translation.

## 3\. Sampling 

This strategy adds variety by choosing a token randomly based on the probability distribution produced by the model. It selects the top higest probable K tokens and sample from them. This method allows for more diverse and creative responses due to a level of randomness. 

To prevent the model from picking any highly improbable tokens, Top-K sampling and Top-P sampling are used. 

**Top-K Sampling** 

The model only considers the top K most probable tokens and redistributes the probabilities among them. For example, if K = 4, the model only looks at the four most likely words. 

**Top-P Sampling**

The model selects the smallest set of tokens whose comulative probability exceeds a threshold P. This is more dynamic than Top-K because the number of tokens in the pool can change depending on how confident the model is about its top choices. 

# How are probabilities obtained? 

Temperature (T) acts as a bridge between the MoE's calculations and the decoding selection. It is a hyperparameter that adjusts the probability distribution before the decoding strategy picks a word. 

**Low Temperature** 

It makes the MoE's output more spiky, heavily favoring the highest probability tokens and making the model more deterministic or predictable. This results in more stable, deterministic, and high-quality safe answers. 

**High Temperature** 

It flattens the distribution, making it more uniform. This allows the decoding step to pick less likely words more often, which results in more creative, diverse, and sometimes surprising outputs. 

**Temperature = 0** 

Setting the temeprature to zero makes the model purely deterministic, behaving exactly like greedy decoding. With a temperature of zero, we expect to see the same output every time in tools like ChatGPT. However, we might see slight variations in output due to GPU hardware. 

# Prompting Strategies

## Zero-Shot and Few-Shot

In the context of Large Language Models, the learning foundation refers to In-Context Learning. We teach the model how to behave through the prompt without changing its weight. 

**Zero-Shot**

We give the model an instruction or a query without any examples. 

**Few-Shot**

We provide several examples of inputs and their corresponding outputs before giving the final query. 

## Chain of Thought (CoT)

Chain of Thought is a technique used to instruct LLMs to break down complex problems into a logical reasoning step before it provides the final answer. CoT is integrated into either zero-shot or few-shot settings. In few-shot CoT, the examples we provide include the reasoning steps leading to the answer, which teaches the model to show its work for the final query. 

## Self-Consistency

Self-Consistency is designed to make CoT even stronger by addressing the fact that a single reasoning path might be flawed. Instead of generating just one answer, the system samples the model multiple times in parallel. It then parses the final answers from these multiple "chains of thought" and uses a majority vote to select the most common answer. 

## How do they work each other? 

### 1\. Prompt Construction 

We start with the learning style (Zero-shot or Few-shot). We then decide if those instructions or examples should include a Chain of Thought.

### 2\. Model Execution 

First, the model receives the prompt (the zero/few-shot context).  Second, the model begins generating tokens. If using CoT, it generates the reasoning rationales first, followed by the final answer. Third, If using Self-Consistency, multiple versions of the step above happen in parallel. As a final step, once all parallel generations are complete, the system performs the majority vote (Self-Consistency) to pick the final answer.
