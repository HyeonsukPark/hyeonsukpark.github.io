The section explains about LLM tuning, specially explaning on how to align pre-trained models with human preferences. It details a three-stage evolution of model training, moving from a pre-training supervised fine-tuning (SFT) to Reinforcement Learning from Human Feedback (RLHF). 

Traditionally, **Supervised Fine-Tuning (SFT)** model was used to train and do LLM tuning based on training on labeled-data. However, it has several limitations. SFT is a standard supervised learning task where the model learns to mimic the provided high-quality data. 

- SFT requires a dataset of high-quality prompt-response pairs. It is extremely time-consuming and diffcult for human annotators to write perfect responses from scratch for every training example.

- SFT models are highly senstivie to the distribution of prompts in the training set. If the dataset has too many examples of a specific type, the model becomes heavily biased toward responding in that particular way. Adding new examples to fix behavior requires re-balancing to avoid over-biasing the model. 

- The SFT process only teaches the model what tokens it should predict. It provides no negative signals to teach the model what it should not predict, making it difficult to discourage unwanted behaviors like rudeness or safety violations. 

- An SFT model might behave as an assistant but still fail to meet specific human preferences regarding tone, safety, or friendliness. For example, it might provide factually correct information but in a blunt or unfriendly way. 

# How RLHF overcomes these Limits?

RLHF was developed to address these gaps by shifting the focus from mimicking data to aligning with human values. 

1.  Instead of writing perfect answers, humans only need to rank exisiting model outputs. It is much easier for a person to compare two responses and say "A is better than B" than to write a perfect response from scratch. 

2.  Unlike SFT, RLHF allows for a nagative signal. By using preference paris (a winning and a losing response), the training process explicitly teaches the model to downweight the characteristics of the losing response. 

3.  RLHF fine-tunes the model on specific dimensions like helpfulness, safety, and tone without requiring the massive effect of rewriting the entire SFT dataset. It allows the model to learn that a "gentler" response is preferred over a "rough" one, even if both are factually accurate. 

4.  While SFT uses static data, RLHF often involves on-policy training where the model generates its own responses and receives feedback on them. This allows the model to explore the space of possible completions and learn from its own current policy rather than just mimicking external data. 

5.  According to the lecture, preference tuning is a specific method used to perfom preference tuning. **Preference tuning** is the third stage of training a large language model (LLM), following pre-training and supervised fine-tuning (SFT).

Let's look at the three steps for LLM model tuning. 

First step is '**pre-training'**. In this stage, a model is initialized and taught about language and code by being fed a massive amount of data. The process teach the model the fundamental structure of language and code so it can predict the next token in a sequence. 

Second step is **'Supervised Fine-Tuning, SFT'**. This stage takes a pre-trained model (from the first step) and teaches it how to behave as an assistant. It focuses on instruction-following by training the model on specific tasks using next-token prediction. 

Third step is **'RLHF'**. It takes the fine-tuned assistant and adjusts it to match human perferences, specifically focusing on nuances like tone, safety, and helpfulness. In this stage, RLHF uses preference pairs, where a model generates two different responses to a prompt and a human ranks which one is better. This is much easier for humans to do, as it is simpler to choose a winner between two options than to write a perfect answer from scratch.

# How is the preference pairs generated?

The foundation of preference tuning is pair-wise preference data. First, a prompt is fed into a model to generate two different responses. These responses are compared by humans or an LLM-as-a-judge. The pair is labeled as a winning response and a losing response. 

RLHF (Reinforcement Learning from Human Feedback) involves two main steps, which are Reward (RM) Model and Reinforcement Learning (RL).

## Stage 1 : The Reward Model (RM)

The role of the Reward Model is to distinguish between good and bad outputs by assigning a scalar score to a given prompt and completion. The model allows for the injection of a nagative signal, teaching the model what it should not generate. This scoring system is used to align the LLM's policy with human values like tone, safety, and helpfulness. Once trained, the Reward Model provides feedback to the LLM during the reinforcement learning stage to maximize the preferred behavior.

-   Prompt → Answer → Reward Model (Scoring system) → **🙂 Good Answer**
-   Prompt → Answer → Reward Model (Scoring system) → **☹️ Bad Answer**

In this scoring system, Bradly-Terry Formulation is used. It defines the probability that response   is better than  , asking "What is the probability that the good answer actually beats the bad answer based on the scores the model gave them?"

The Logic is, if the Reward Model gives the good answer a higher score than the bad answer, the probability of the good answer being better should be close to 1.0 (if the highest score is 1.0). And, we look at the difference between the scores.

The model is trained to maximize the score of the good response relative to the bad one. This is achieved by minimizing the negative log-likelihood (Loss Function) of the human preference data. Loss Function measures how wrong the model's scores were compared to human scores and tells it how to fix them. 

## Stage 2 : Reinforcement Learning (RL)

Once the RM is trained and frozen, the LLM is tuned using an RL algorithm, typically PPO (Proximal Policy Optimization). The LLM itself acts as the agent, where the action is predicting the next token. However, the stage has a potential risk.  

A major risk of RLHF is reward hacking, where the model finds a way to maximize the reward score without fulfilling the intended objective. If a reward model favors long responses, the LLM might start generating fluff to get a higher score, even if the quality decreases. 

To prevent the model from drifting too far from its original SFT state, a KL divergence penalty is added to the loss function. The PPO loss function includes a KL divergence term that measures how far the current model's distribution has drifed from the original SFT base model. It is important for the model to stay close to the base model, while ensuring the model retains the broad knowledge it gained during pre-training and SFT.

**Proximal Policy Optimization (PPO)** and **KL (Kullback-Leibler) Divergence** are core components used in the reinforcement learning stage of RLHF. They align large language models with human preferences.  

## 1\. PPO

PPO is a reinforcement algorithm used to update the parameters of an LLM based on reward signals. 

-   LLM acts as the agent
-   Input prompt is the state 
-   The generated tokens are the actions 
-   The output probability distribution is the policy

During RLHF, a prompt is fed to the LLM, which generates a completion. This output is evaluated by a frozen reward model trained on human preference data. PPO then updates the LLM's weights to maximize the expected score of generated completions.  

In this stage, rather than directly optimizing raw reward scores, PPO optimizes an advantage estimate, measuring how much better a response is compared to an expected baseline estimated by a value function. This reduces variance and makes RL training significantly more stable.

## 2\. KL Divergence

KL Divergence is a statistical measure that quantifies how much one probability distribution differes from another reference probability distribution. 

In PPO for RLHF, a KL penalty term is added to the objective function. It measures the mathematical distance between the token probability distribution of the active policy being trained and that of a frozen reference model, which is the initial SFT model. 

KL Divergence is essential because, 

-   Reward models are imperfect approximations of human preference. Without a KL penalty, PPO would generate repetitive or nonsensical phrasing that artificially gets high reward scores. 
-   The initial SFT/pre-trained model already processes vast general word knowledge and language capabilities. Constraining the draft ensures the model aligns its style/tone without erasing foundational skills. 

In the RLHF process, the loss function maximizes the reward from the reward model while simultaneously subtracting a KL penalty weighted by a coefficient. PPO drives the LLM toward generating outputs that earn higher ratings, while KL divergence acts as a guardrail keeping the model close to its original foundational distribution. 

## Limitation and Challenges with PPO and RL

PPO requires four separate models during training, which makes the process quite computational extensive with heavy memory. Also, RLHF is a strict two-step process, with a reword model and reinforcement learning. If flaws or noise are discovered in the reward model during the RL stage, the entire pipeline must be restarted. 

# Best-of-N (BON) Strategy

The Best-of-N (BON) strategy is a non-RL approach that needs a trained reward model but avoids the complexities of RL training. 

First, it takes an input prompt and feed it to the frozen SFT model. Second, it generates N different completion candidates by settin a positive temperature. Third, it passes all N completions through the frozen reward model to get a scalar score for each. finally, it selects and returns the candidate with the higest reward score to the user. 

The approach bypasses the RL/PPO training loop and hyperparameter tuning. However, it requires generating N full completions and scoring all of them every time a user sends a prompt, making the process repetitive. 

# Direct Preference Optimization (DPO)

DPO is a preference tuning technique that replace the complex reinforcement learning loop with a simple, direct supervised loss function. 

During training, standard PPO requires 4 large models (Policy, Reference, Reward, Value) in memory. DPO relies entirely on the implicit reward formulation, needing only 2 models (Active Policy Model and Frozen Reference Model). 

There is no separate reward model to train or maintaon, and no complex RL hyperparameters.
